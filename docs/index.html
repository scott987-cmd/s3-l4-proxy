不解密、不改写、不持有凭证的对象存储通路

使用公网负载均衡 TCP 443 透传与 nginx stream，把 S3 客户端流量转发到客户网络中的 S3 兼容对象存储私网 endpoint。代理不终结 TLS、不修改 HTTP/S3 请求、不保存对象存储凭证—— 客户端到对象存储的加密与认证签名保真是端到端的。 转发路径短，性能接近网卡上限；没有证书、凭证与会话状态需要照看，日常人力投入趋近于零； 数据面全部基于开源 nginx，无授权费用、无厂商锁定。

一、方案定位

四段链路，没有一段理解 S3 语义

SaaS 机房通过固定公网出口访问客户负载均衡，负载均衡将 TCP 443 分发到客户 ECS 上的 nginx stream，ECS 再经客户内网访问对象存储私网 endpoint。全链路只搬运字节。

端到端 TLS

负载均衡和 nginx 均不解密，代理主机不部署对象存储证书或私钥。Host、SNI、path、query、Authorization、请求体及签名头保持原样。

无状态扩展 · 通用数据面

nginx stream 不保存会话状态，加 ECS 即可横向扩容。网络层不绑定厂商；兼容性由 endpoint、证书、寻址模式和认证协议决定。

二、方案优势与使用前提

转发路径越短，越快、越稳、越省事、越便宜

代理只做一件事：把 TCP 字节原样搬过去。少做的每一件事，都换来一份性能、一份稳定性、一份人力与成本的节省。

性能：代理不构成瓶颈

不解密、不重组、不解析 HTTP、不重新计算签名——没有 TLS 终结与二次握手，也没有应用层缓冲。实测单连接 78–98 MB/s，瓶颈已接近测试实例网卡上限，转发本身不带来额外损耗；要更高吞吐，换更大带宽的实例即可线性提升。

稳定性：故障面小到可以穷举

不持证书就没有证书过期与轮换引发的故障；不持凭证就没有密钥失效类故障；无会话状态则单节点异常只需被负载均衡摘除，连接重建即可恢复。固定 upstream 消除了变量 resolver 路径导致的周期性连接重置；跨可用区 N+1 与失败自动回滚兜住剩余风险。

人力：部署一条命令，日常一条命令

部署、巡检、验收、运维各一条命令，health 的退出码可直接接监控告警。证书轮换零动作、密钥轮换零动作、后端 DNS 变更由定时器自动跟进、扩容只是把同一份配置装到新节点再加进负载均衡——没有需要人盯着的日常操作。

成本：全开源，无授权费用

数据面只依赖 nginx + ngx_stream_module，来自发行版官方仓库，无闭源组件、无 license 费用、无按量计费的中间件、无厂商锁定。全部资源开销就是两台 ECS 与一个公网负载均衡；不解密不解析，CPU 花在网络 I/O 上，普通规格实例即可承载。

兼容性：不解析协议，就没有「适配某个厂商」这件事

厂商在签名算法变体、path-style 与 virtual-hosted 寻址、私有扩展头、非标准错误响应体、自有鉴权机制上的差异，全部原样透传。任何需要理解 S3 协议的中间件都必须逐个厂商适配这些方言，而中小厂商与自建存储（MinIO、Ceph RGW）恰恰在这些点上差异最大——本方案不解析，因此不存在「该厂商尚未适配」的问题。能不能通，只取决于客户端与对象存储两端自己是否谈得拢，与代理无关。

六项使用前提

  • ✓ECS 能解析并访问 S3_BACKEND_HOST:PORT，生产优先私网 endpoint
  • ✓客户端用 S3_CLIENT_HOST 完成 SNI 与签名，且解析指向负载均衡
  • ✓对象存储证书覆盖该 hostname，或有等价 endpoint/SNI 组合
  • ✓认证协议被目标 endpoint 接受，region / service / endpoint family 匹配
  • ✓负载均衡为 TCP 四层监听，链路无设备改动 TLS 或应用层请求
  • ✓至少两台跨可用区 ECS，配 TCP 健康检查与 N+1 冗余

六类不适用场景

  • ✗需要虚拟 AK/SK 转换、STS 获取、凭证托管、代签或重签
  • ✗需要改写 Host/path、path-style 与 virtual-hosted 转换
  • ✗必须在代理层实施 WAF、对象级限流、租户鉴权或内容扫描（对象存储侧的 IAM 与审计不受影响）
  • ✗客户端 hostname 不被后端证书覆盖且无兼容组合
  • ✗客户端无法生成目标对象存储要求的认证协议
  • ✗无法配置负载均衡 ACL 与多后端高可用，只能裸露单台 ECS 公网地址
三、安全设计

五层安全边界：对绝大多数场景已经足够

代理机上真正持有的资产只有「网络可达性」——没有明文、没有凭证、没有私钥。因此控制项全部围绕收敛可达性展开，被攻破时的损失面也被压到最小。

数据层
客户端侧加密
敏感数据出客户端机房前使用客户 KMS 加密，代理与存储侧只接触密文。
传输层
端到端 TLS
负载均衡与 nginx 不终结 TLS，不保存证书和私钥。
接入层
负载均衡 ACL 与安全组
只放行客户端固定出口 IP；ECS 443 只接受负载均衡或批准来源。
代理层
主机与出向收敛
专用主机只监听 443/22；出向仅允许 DNS、运维依赖和对象存储私网 endpoint。
存储层
最小权限与来源限制
专用子账号/角色只授权目标桶必要动作；桶策略限制代理实际来源地址。
✓
为什么这套边界对多数客户已经够用。鉴权与对象级审计的权威点本来就在对象存储自身——IAM 主体、桶策略、审计日志都在那一侧完整生效，代理层不重复实现，并不等于这些能力缺失。反过来，任何在链路中间解密的做法，都会新增一个同时持有明文与密钥的组件，也就多出一个必须防守、必须轮换、必须审计的位置。本方案不解密、不持凭证、不存私钥，攻破代理机拿不到数据也拿不到密钥，能拿到的只有一条被 ACL、安全组和桶策略三重收敛过的网络可达性。
!
需要知道的可见性边界。代理看不到加密后的 HTTP/S3 语义，因此不在代理侧记录 bucket、object key、access key 或请求动作，nginx stream 只记录连接来源、时长、字节数、状态和上游地址。对象级追溯请取自客户端与对象存储审计日志；代理不重复采集，也就不引入新的数据留存面。
!
先确认实际来源再写桶策略。四层之下对象存储看到的是 ECS 访问私网 endpoint 时使用的源地址/网段——不是客户端出口 IP，也不一定是 ECS 公网 IP。必须通过审计日志或网络设计确认真实值，猜测的结果要么放得过宽，要么直接锁死生产。
✗
不要默认叠加 Deny + Principal:"*" + NotIpAddress。默认隐式拒绝已提供兜底，而显式 Deny 会覆盖所有 Allow——包括你还需要的那些。条件键用 volc:SourceIp，不要用 tos:SourceIp；删除权限仅在业务明确需要时才加 tos:DeleteObject。
五、软件包与一键使用

部署 → 巡检 → 验收 → 运维

四个阶段各有一条命令。软件包与 config.example.env 不包含 AK/SK，真实凭证只在验收进程环境中临时提供。

STEP 01

一键部署

按需装 nginx 与动态 stream 模块，渲染配置，应用运行时基线，装 DNS reload timer。

cp config.example.env config.env sudo bash scripts/\ install_l4_proxy.sh \ CONFIG=config.env
STEP 02

一键巡检

只读检查服务、监听、配置、上游与安全基线。退出码 0 全通过 / 1 有告警 / 2 有失败。

bash scripts/\ verify_l4_proxy.sh \ -c config.env
STEP 03

一键验收

节点健康 + 本机穿透 + 负载均衡诊断，加 RUN_SPEED=1 走真实 PUT/GET/MD5。

S3_ACCESS_KEY=... \ S3_SECRET_KEY=... \ bash scripts/\ acceptance_l4_proxy.sh \ CONFIG=config.env RUN_SPEED=1
STEP 04

一键运维

状态、健康、reload、restart、上游探测、连接统计，以及紧急解除出向锁定。

bash scripts/ops_l4_proxy.sh \ status|health|reload|\ restart|upstream|conns \ CONFIG=config.env
!
专用代理机默认 MAIN_MODE=replace，会安装已知的 stream-only nginx 主配置。与现有 nginx HTTP 服务混部时必须显式设置 MAIN_MODE=auto 和 DEDICATED_PROXY_HOST=0，并单独评审端口与变更影响。
六、变更与回滚

先备份，再改动，失败自动还原

配置脚本在写入前创建运行级备份；nginx -t 失败或过程报错时，自动恢复 nginx、systemd limit、sysctl 与防火墙状态。

四、厂商兼容性

不解析协议，所以没有「适配某个厂商」这件事

代理只搬运 TCP 字节，厂商在签名算法、寻址模式、自定义头、错误格式上的差异全部原样透传——这正是它对长尾对象存储兼容性最好的原因。

✓
兼容性风险在网络层被降到最低。任何需要理解 S3 协议的中间件，都必须逐个适配各厂商的方言：SigV4 的变体、path-style 与 virtual-hosted 寻址、厂商私有的扩展头、非标准的错误响应体、以及各家自有的鉴权机制——中小厂商与自建存储（MinIO、Ceph RGW）在这些点上差异最大，也最容易踩坑。本方案不解析这些内容，因此不存在「该厂商尚未适配」的问题：能不能通，只取决于客户端与对象存储两端自己是否谈得拢，与代理无关。
对象存储结论校验重点
火山 TOS作者实测环境使用 tos-s3-* endpoint family；service 为 s3。
AWS S3L4 数据面兼容S3/VPC endpoint、region、service 与证书覆盖的 client host。
阿里 OSSTCP 透传兼容确认客户端使用 OSS 支持的认证协议或兼容模式。
华为 OBSTCP 透传兼容确认 endpoint、证书和签名算法一致。
MinIO / Ceph RGW通常兼容私有 CA、path-style/virtual-hosted 和 SigV4 配置。
