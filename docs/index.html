Verified in production

A proxy that refuses to look at your data.

Layer-4 TCP 443 passthrough from a load balancer to S3-compatible object storage on a private endpoint. TLS is never terminated, the request is never rewritten, and no storage credential ever touches the proxy — so encryption and signature bytes stay intact from client to bucket.

Architecture

Four hops, zero interpretation

Every box on this path moves bytes without understanding them. The only components that know what an S3 request means are the two ends.

Trade-off

Choose L4 for a transparent path, L7 to rewrite semantics

This is not a gateway with fewer features. It is a different layer, and the distinction decides whether it fits.

RequirementL4 TCP passthroughL7 gateway
TLS and signature passed through untouched✓ recommendedneeds strict signature preservation
Virtual AK/SK, delegated or re-signing✗✓
Host / path rewrite, addressing-style conversion✗✓
Object-level authz, rate limiting, audit✗ HTTP is opaque✓
WAF header / body inspection✗✓
✗
Do not try to approximate L7 controls with TCP rules. If you need object-level audit, per-tenant authorization, or credential translation, this is the wrong layer — and no amount of proxy configuration changes that.
Quick start

Deploy, verify, accept

Every script is idempotent and backs up the system state before writing anything. A failed nginx -t rolls the whole run back automatically.

Configure

Copy the template and fill in your endpoints. Real credentials never go in this file.

proxy node · shell
# on the ECS proxy node
git clone https://github.com/scott987-cmd/s3-l4-proxy.git
cd s3-l4-proxy
cp config.example.env config.env

# edit: S3_BACKEND_HOST, S3_CLIENT_HOST, S3_REGION, LISTEN_PORT, CLB_IP

Install

Installs nginx and the stream module if missing, renders the config, applies the runtime baseline, then verifies itself.

proxy node · shell
sudo bash scripts/install_l4_proxy.sh CONFIG=config.env
bash scripts/verify_l4_proxy.sh -c config.env

# exit 0 = all pass · 1 = warnings · 2 = failures

Accept

A real PUT / GET / MD5 round trip through the load balancer. Credentials come from the process environment and are never written to disk.

client machine · shell
S3_ACCESS_KEY=... S3_SECRET_KEY=... \
  bash scripts/acceptance_l4_proxy.sh CONFIG=config.env RUN_SPEED=1
✓
Reference result. Deployed from the release archive onto a freshly reinstalled CentOS Stream 9 host (nginx 1.20.1, dynamic stream module): inspection PASS=20 WARN=1 FAIL=0 — the single warning is the egress lock being off by security default. Through a public CLB against Volcengine TOS: 1 MB PUT 200, GET 200, MD5 match; 100 MB / 500 MB single-connection transfers reached roughly 78–98 MB/s, close to the test instance NIC ceiling.
Day two

One entrypoint for everything after deploy

Wire health into monitoring — it exits 0 / 1 / 2 for pass / warnings / failures.

ops_l4_proxy.sh
bash scripts/ops_l4_proxy.sh status   CONFIG=config.env  # service, listener, upstream, config
bash scripts/ops_l4_proxy.sh health   CONFIG=config.env  # full verification
bash scripts/ops_l4_proxy.sh conns    CONFIG=config.env  # connection states and peers
bash scripts/ops_l4_proxy.sh upstream CONFIG=config.env  # DNS + timed HTTPS probe
sudo bash scripts/ops_l4_proxy.sh reload CONFIG=config.env

# emergency: remove only the dedicated S3_L4_EGRESS chain
sudo bash scripts/ops_l4_proxy.sh unlock-egress CONFIG=config.env

Connection-level logs

Source, duration, bytes, status, upstream and connect time — rotated daily, 15 generations. Never bucket or object key: those bytes are encrypted.

Backup and rollback

nginx config, stream config, systemd limits, logrotate, sysctl and iptables are captured before any write and restored automatically on failure.

Stateless scaling

No session state to migrate. Install the same config on a new host, add it to the backend group, wait for the health check.

Configuration

The settings that matter first

Everything is an environment variable. Defaults come first, then config.env, then command-line KEY=VALUE arguments. Full table in the configuration reference.

VariableDefaultWhat it controls
S3_BACKEND_HOSTtos-s3-<region>.ivolces.comThe endpoint the ECS host connects to. Use the private endpoint in production. The default is Volcengine TOS — set it explicitly for any other vendor.
S3_CLIENT_HOSTemptyHostname the client uses for TLS SNI and signing. Must be covered by the backend certificate.
LISTEN_PORT443nginx stream listener. Must match the CLB backend port and its health check.
MAIN_MODEreplacereplace installs a stream-only main config on a dedicated host. Use auto with DEDICATED_PROXY_HOST=0 when co-locating with an nginx HTTP service.
ENABLE_PROXY_PROTOCOL0Turn on only if the CLB listener also sends PROXY protocol. A one-sided setting breaks every plain TLS client.
EGRESS_LOCK0Restricts outbound traffic to DNS, SSH, EXTRA_ALLOW and the resolved backend, via a dedicated chain that never flushes existing rules.
DNS_RELOAD_INTERVAL5minHow often nginx is gracefully reloaded so the fixed upstream picks up backend DNS changes.
Security

What a compromised proxy would actually yield

The design goal is to make that answer boring. Network reachability is the only real asset on the host.

Object data — ciphertext only

TLS is never terminated on the path. Encrypt with your own KMS before data leaves the client side and the proxy handles nothing but opaque bytes.

Credentials — none present

No AK/SK, session token, signing key, certificate or private key is stored or read anywhere on the proxy path.

Metadata — not visible

Bucket, object key, access key and action are inside the encrypted stream. Object-level audit must come from the client or the storage's own audit log.

Reachability — the real asset

Narrow it: CLB ACL to fixed client egress, security group to the CLB only, optional egress lock, and a bucket policy pinned to the proxy's real source address.

!
Get the source address from the audit log, not from a guess. Under L4 the storage sees the address the ECS host uses to reach the private endpoint — not the original client's egress IP, and not necessarily the ECS public IP. Guessing either fails open or locks out production.
Go-live

Production checklist

Ten of these are checked automatically by verify_l4_proxy.sh. The rest are decisions only you can make.

Two or more ECS nodes across availability zones behind one L4 CLB
CLB TCP health check targets the same port as business traffic
CLB ACL and security group allow only the client egress and the CLB
nginx stream module loaded and nginx -t passes
Active config uses proxy_pass s3_backend, never proxy_pass $…
worker_rlimit_nofile and systemd LimitNOFILE at least 65535
Stream log collected and rotated
DNS reload timer enabled
PROXY protocol setting matches the CLB listener on both sides
Egress lock enabled only after validating every dependency
Bucket policy principal, resources and source IP saved and verified
Real PUT / GET / MD5 through the CLB passes before cutover
